# Keeper Bot & Attestations

The **Xero Keeper Service** (located in [`services/keeper`](https://github.com/hackcat29/xero-protocol/tree/main/services/keeper)) is an autonomous TypeScript daemon responsible for corporate action monitoring, multi-sig attestations, index synchronization, and LP yield harvesting.

---

## 🤖 Keeper Responsibilities

1. **Corporate Action Monitoring & Attestation:** Monitors off-chain corporate action data (forward splits, reverse splits, cash dividends). When an action is detected, it computes the canonical payload and calls `CorporateActionEngine.report()` using an address with `REPORTER_ROLE`.
2. **Vault Index Synchronization:** Regularly triggers `vault.sync()` across active vaults to settle effective actions and adjust the sanitized `dividendIndex`.
3. **Maturity Settlement:** Automatically triggers `_sync()` when a vault reaches its maturity timestamp $T$, permanently freezing the `maturityIndex`.
4. **LP Yield Harvesting:** Calls `market.harvestYield()` on active `XeroYieldMarket` pools, sweeping accrued underlying dividends into pool quote reserves.
5. **Solvency Invariant Watchdog:** Periodically evaluates `vault.invariantHolds()` to verify 100%+ collateralization.

## ⚙️ Environment Configuration

Copy the example environment configuration file:
```bash
cp services/keeper/.env.example services/keeper/.env
```

### Environment Variables:
```ini
# Base Mainnet RPC
RPC_URL=https://mainnet.base.org

# Path to deployment address book (generated by DeployBaseProduction)
DEPLOYMENT=../../deploy/base-mainnet.json

# Reporter private key (granted REPORTER_ROLE on CorporateActionEngine)
REPORTER_PRIVATE_KEY=0x...

# Keeper private key for permissionless maintenance (sync, harvest)
KEEPER_PRIVATE_KEY=0x...

# true = log intended transactions without sending; false = execute on-chain
DRY_RUN=false

# Polling interval in seconds
POLL_SECONDS=60

# Attest unsupported actions (mergers, spin-offs...) to halt stripping safely
AUTO_HALT=true

# Optional alert webhook for Slack or Discord
ALERT_WEBHOOK_URL=https://hooks.slack.com/services/...
```

## 🚀 Running the Keeper

### 1. Installation
```bash
cd services/keeper
pnpm install
```

### 2. Run in Dry-Run Mode (Testing)
Verify that feeds and RPC connections are functional without submitting on-chain transactions:
```bash
DRY_RUN=true pnpm run dev
```

### 3. Production Deployment (Node / PM2)
```bash
# Build TypeScript
pnpm run build

# Start with PM2 process manager
pm2 start dist/main.js --name "xero-keeper-base"
pm2 logs xero-keeper-base
```

## 🚨 Alerts & Emergency Escalation

If an unexpected multiplier spike is detected or a vault halts due to an unannounced corporate reorganization (e.g. cash buyout or spin-off):
* The keeper immediately issues an emergency notification to `ALERT_WEBHOOK_URL`.
* The vault automatically transitions into **Frozen** state, preventing new deposits while preserving user withdrawal rights.
